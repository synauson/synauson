# Synauson gRPC API Reference

The `synauson.v1.Syn` service. Its protos are published in [synauson/api](https://github.com/synauson/api): `synauson/v1/synauson.proto` lists every RPC, and the other `.proto` files in that directory define the messages. Every instance also serves the operator's `synauson.v1.SynAdmin` ([Admin service](#admin-service)) and `grpc.health.v1.Health`.

The proto comments are the field-level reference, published with a reference generated from them (`docs/api.md` in synauson/api). This page is the longer guide to the same API.

## Contract conventions

These are frozen with synauson/api 1.0.0, its first release: changing any of them later is a `synauson.v2`.

- **Ids** are chosen by the caller: 1 to 128 characters from `A-Z`, `a-z`, `0-9`, `.`, `_` and `-` (conference, participant, speaker and utterance ids alike). The engine checks them, so jsyn refuses the same ids; anything else fails with `INVALID_ARGUMENT`, reason `INVALID_ID`, metadata `field`. A speaker's default id is the participant id plus `.speaker`, so adding a participant with `tts` and no `speaker_id` fails with `INVALID_ID` when its id is over 120 characters. They are plain ids, not AIP-122 resource names: the API has no per-resource Get or List to address.
- **Errors**: every failed call carries a `google.rpc.ErrorInfo` (domain `synauson.com`, an UPPER_SNAKE_CASE reason, string metadata with lowerCamelCase keys such as `conferenceId` and `lastSeq`), as AIP-193 requires, so messages are free text and may be reworded. `errors.proto`'s documentation-only `ErrorReason` enum lists every reason with its code and metadata. One reason per client action (AIP-193): a rejected license is `FAILED_PRECONDITION` (`LICENSE_REJECTED`), a model or pool still loading `UNAVAILABLE` (`MODEL_LOADING`), each `RESOURCE_EXHAUSTED` cause its own reason. An error naming one bad field also carries a `google.rpc.BadRequest` violation with the field path. Clients match the reason, never the code: the gRPC library returns `RESOURCE_EXHAUSTED`, `OUT_OF_RANGE` (tonic, for an oversized message), `UNAVAILABLE` and `CANCELLED` itself, without an `ErrorInfo`.
- **Integers are signed** (AIP-141: Java and JSON users can't take unsigned 64-bit values), one width per concept: seqs, ids and event times `int64`, counts, ports and configured durations `int32`.
- **Wall-clock instants are `google.protobuf.Timestamp`** named `*_time` (AIP-142): `event_time` on every event, `create_time`, `capture_time`, `file_expire_time`, `license_expire_time`, `peak_time`, and the usage service's `last_contact_time`, `grace_end_time`, `pause_time` and `refuse_time`. Times inside a stream stay integer ms named `*_ms`, each comment naming its clock: conference time (the agent stream), transcription audio time (the transcript stream), or an utterance's own audio; durations say so.
- **Presence** follows AIP-149: `optional` only where unset differs from zero (a default applies, or "not known" differs from 0), never on message-typed fields, where it changes nothing. Always-zero fields were removed (`SipStats.rtt_ms`, `DtmfEvent.duration_ms`). Retired fields were deleted, not `reserved`: v1 retypes enough of the old fields that a 1.7 server and a v1 client can't talk anyway (the minimum server is 1.8.0), and no other published release had them. The one exception is `LicenseInfo` field 8, v1.7.1's string `plan`: its number is `reserved` because its name came back as field 11 with another type (the name can't be reserved while field 11 uses it). From the first synauson/api tag on, a removed field's number and name are `reserved`. An enum field with a value in every state has no `optional` and never sends `*_UNSPECIFIED` (`LicenseInfo.plan`); one with no value in some states keeps `optional` and is absent there (`LicenseInfo.source` without a license file, `SttCapacityInfo.source` before the capacity is known).
- **Enums**: closed sets are top-level proto enums with buf's prefixes (`PARTICIPANT_KIND_SIP`), zero `*_UNSPECIFIED` and never sent; every response enum and documented string set says it may gain values. Open or standard sets (`limited_by`, `cpu_flags`, entitlement codes, codecs as RTP payload format names, WebRTC states) are strings with their values listed. A request enum value the server doesn't know is `INVALID_ARGUMENT`, never read as the default.
- **Files**: today's topic files are the v1 layout (one Python module each).
- **SRTP keys** are `local_key` and `remote_key` inside `SrtpConfig`, where the message says what they are for, and `local_srtp_key` and `remote_srtp_key` on flat messages (`ReserveSipParticipantRequest`, `SipRemoteMedia`); both pairs are intentional. Jitter names say which statistic: `SipStats.avg_jitter_ns`, `WebRtcStats.max_jitter_ns`.
- **Departures from the AIPs**, written down once here: plain ids instead of resource names (above); `_ms` integers instead of `google.protobuf.Duration`; required fields said in comments ("Required.") instead of importing `google.api.field_behavior`; buf's enum value prefixes instead of AIP-126's unprefixed nested values; preposition names kept as local style (`at_ms`, `since_speech_end_ms`, `limited_by`, `included_by`); counts as plural nouns (`workers`, `threads`, `packets_received`, as RTP and the W3C statistics name theirs) with `_count` only where the plural alone reads as a list (`participant_count`); `GetCapabilities` and the event streams use per-RPC request and response messages and never `google.protobuf.Empty` (Buf's style).
- **Retry safety** is in each RPC's comment: reads, `MuteParticipant`, `SetAudioRoutes`, `UpdateTurnConfig`, `CancelUtterance`, `AddWebRtcIceCandidate` and `ShutdownServer` are safe to retry; adds and `StartConference` fail with `*_ALREADY_EXISTS` on a retry after a lost reply (which then means the first call worked); `Speak`, `SendDtmf`, `AddPriorityAudioFiles` and `ForceEndTurn` are not retry-safe (a timed-out call may still have run; Speak is documented, and a part number may be added later, additively). `GetCapabilities` reports `server_version` and `api_version` (the synauson/api release the server implements).

## Transport

- **Keepalive**: the server sends an HTTP/2 PING every 60 s and closes a connection that doesn't answer within 20 s, so a vanished client's streams end; accepted sockets get TCP_NODELAY and TCP keepalive (`TcpIncoming`). Clients should not send keepalive pings more often than about once a minute; the agent stream's heartbeats are the supported way to notice a dead stream.
- **Limits**: at most 1024 concurrent streams per connection; messages up to 4 MiB each way.
- **Compression**: none. tonic answers a compressed request with `UNIMPLEMENTED`; clients must not compress requests.
- **Deadlines**: clients set one on every unary call and none on streams.
- **Health**: `grpc.health.v1.Health` reports the overall status ("") and `synauson.v1.Syn` and `synauson.v1.SynAdmin`, outside the token check. "" is liveness: SERVING while the process runs. `synauson.v1.Syn` is readiness: NOT_SERVING whenever the server won't start new work, for example while the license starts nothing new (`rejected`, `disconnected`, or an expired developer license), while this instance holds no share of a limited conference pool (none leased yet; a full pool still serves) or during a shutdown, and later releases may add causes, so clients treat any NOT_SERVING alike ([deployment, Health](deployment.md#health)). All three turn NOT_SERVING as soon as a shutdown starts (the `ShutdownServer` RPC, SIGTERM or SIGINT); from then on `StartConference` fails with `UNAVAILABLE`, `SERVER_SHUTTING_DOWN`. Once its conferences are terminated, a stopping server waits at most 2 s for open connections (health watchers, streams a client stopped reading) before it exits anyway.
- **Auth**: `--auth=token` checks `authorization: Bearer <token>` metadata on `Syn` and `SynAdmin` (constant-time); a refusal is `UNAUTHENTICATED`, reason `INVALID_TOKEN`. With `--tls-cert` and `--tls-key` it serves TLS so the token never crosses the network in clear. `--auth=mtls` needs client certificates. Flags: [deployment](deployment.md).
- No client- or bidi-streaming RPC, so gRPC-Web proxies can serve every call.

## Conference lifecycle

### `StartConference`
- **Request**: `StartConferenceRequest { conference_id: string }`
- **Response**: `StartConferenceResponse { conference_id: string }`
- **Errors**: `INVALID_ID`, `CONFERENCE_ALREADY_EXISTS`, `CONFERENCE_LIMIT_REACHED` (the operator's `--max-conferences` cap, checked first), `CONFERENCE_POOL_LIMIT_REACHED` (`RESOURCE_EXHAUSTED`: the license's concurrent conferences with their burst are in use; metadata `inUse`, `limit`, `ceiling`, `scope`, `license`), `LICENSE_SHARE_PENDING` (`UNAVAILABLE`: this instance holds no conference share yet; metadata `pool`, `scope`, `license`), `LICENSE_REJECTED`, `LICENSE_DISCONNECTED`, `LICENSE_EXPIRED` (`FAILED_PRECONDITION`; `LICENSE_EXPIRED` is a license that expired and starts nothing new, today only a developer license), `SERVER_SHUTTING_DOWN` (`UNAVAILABLE`, a shutdown started). Both caps apply and the smaller wins.

### `TerminateConference`
- **Request**: `TerminateConferenceRequest { conference_id: string }`
- **Response**: `TerminateConferenceResponse {}`
- **Errors**: `CONFERENCE_NOT_FOUND`.

### `GetConference`
- **Request**: `GetConferenceRequest { conference_id: string }`
- **Response**: `GetConferenceResponse { conference_id, participants, create_time }`; each participant's `kind` is a `ParticipantKind` (`PARTICIPANT_KIND_FILE`, `_RECORDING`, `_SIP`, `_WEBRTC`). A SIP reservation not yet connected is left out. Mutes, routes and reservations are write-only: nothing reads them back yet (adding that later is additive).
- **Errors**: `CONFERENCE_NOT_FOUND`.

## Licensing

Every license grants every AI capability (VAD, turn detection, STT, TTS) on every session. Licenses differ in two independent pools, and both apply: **concurrent AI sessions** (the Free base of 4 plus the sessions bought) and **concurrent conferences** (the Free base of 10 plus the conferences bought), each with the one `overdraft` burst on its bought part only. A conference takes one conference from its start until it ends, with or without AI; each participant in it using any AI capability also takes one session, whatever it uses; participants without AI take none. A Free key buys neither, so it runs up to 10 conferences at once with at most 4 AI participants across them. The plan (`LicenseInfo.plan`, jsyn's `license.plan`) is Free, paid (something bought, or unlimited), developer or unlicensed (no license in force): a developer license has the Free pools, for development and testing only, and when it expires it starts nothing new (`LICENSE_EXPIRED`) until Synauson renews it, where a Free or paid license falls to the Free plan. Operators: [deployment, licensing](deployment.md#licensing).

### `GetCapabilities`
- **Request**: `GetCapabilitiesRequest {}`
- **Response**: `GetCapabilitiesResponse { server_version, api_version, license, limits_scope, overdraft, capabilities, models, onnx_runtime, stt, sessions, resources, calibration, tts, usage_service, conferences }` (the old conference limits, `CapabilityInfo.streams` and `SttCapacityInfo.calibrated` are gone, their numbers left free: no published release had them). `server_version` is the server's release; `api_version` the synauson/api release it implements, so a client built from a newer one knows to expect `UNIMPLEMENTED` and unset fields.
  - The closed sets below are top-level proto enums over gRPC: `LicenseState`, `LicenseSource`, `LicensePlan`, `LimitsScope`, `UsageContact`, `PoolLevel` (both pools' `level`), `ModelState`, `OnnxRuntimeState`, `PoolState` (the `stt` and `tts` states) and `ValueSource` (every `source`). Their values are the names below in the enum's form (`valid` is `LICENSE_STATE_VALID`, `near-limit` is `POOL_LEVEL_NEAR_LIMIT`, `developer` is `LICENSE_PLAN_DEVELOPER`, `air-gapped` is `USAGE_CONTACT_AIR_GAPPED`); `allow-all`, an unlimited license that only test builds run on, is `LICENSE_STATE_VALID`, so no `_UNSPECIFIED` value is ever sent. jsyn reports the names as they are. `limited_by`, `cpu_flags` and entitlement codes stay strings; the snapshot's cgroup version is the `CgroupVersion` enum. The plan is one field everywhere: `LicenseInfo.plan` (`LicensePlan`) over gRPC and `license.plan` (`free`, `paid`, `developer`, `unlicensed`) in jsyn's JSON; jsyn 1.6 and natives before 1.8.0 used that JSON name for `all` or `none`, which is gone.
  - `license`: `state`, the standing: `valid`, `expiring` (within 14 days of expiry; full function), `offline` (usage reports have not reached usage.synauson.com for an hour or more; full function until 7 days after the last one that did, paused while Synauson's outage notice is up), `expired` (a Free or paid license runs on the Free plan: every AI feature, 4 concurrent AI sessions and 10 concurrent conferences, no burst; an expired developer license starts nothing new), `disconnected` (7 days without a report reaching usage.synauson.com: no new conference or participant starts until one does), `invalid-kept-last-valid` (a renewal brought an illegal or unverifiable license; the last valid one stays in force), `rejected` (no new conference or participant starts either); test builds also report `allow-all`. Calls in progress continue in every state, including calls over the Free pool. Then a one-line description, id, `display_name`, where the license file came from, its expiries (`file_expire_time`, `license_expire_time`), `days_remaining` (to expiry, or when `offline` until new calls stop without contact) `problem` (a refused renewal, a failing license check, or why new work is refused) and `plan`, always set: `LICENSE_PLAN_FREE`, `_PAID`, `_DEVELOPER` or `_UNLICENSED`. It is the license's own plan, Free once a Free or paid license expires, still `_DEVELOPER` once a developer license expires, the license's own while `disconnected` (`state` says nothing new starts), and `_UNLICENSED` when `rejected`; allow-all (test builds) reads `_PAID`. A Free key is `valid`, plan Free, with `sessions.limit` 4 and `conferences.limit` 10. The server doesn't start without a license file that still works (renewed through usage.synauson.com, or within 7 days of the last report that got through), nor offline (`--offline`, jsyn `offline`) without the usage receipt an earlier online run kept in the state directory (an air-gapped license needs none); the JNI adapter throws `PermissionDeniedException` (reason `NO_LICENSE`, JNI only).
  - `sessions` and `conferences` (each a `PoolUsage`): the license's two pools on this instance. For `sessions`: `limit` (the Free base plus the purchased sessions; absent = unlimited), `in_use`, `ceiling` (the most admitted: the base plus the purchased sessions with their `overdraft` burst), `level` (`ok`, `near-limit` from 80% of the limit, `overage` above it, `full`), `peak` / `peak_time`, the most sessions at once since start, for true-up, and `base` (4; 0 while nothing new starts) and `purchased` (absent = unlimited). The pool is the license's, shared by all its instances: `limits_scope` is `LIMITS_SCOPE_LICENSE` (`LIMITS_SCOPE_INSTANCE` for an air-gapped license; jsyn reports "all instances of this license" and "this instance"), and `usage_service` shows this instance's share. `conferences` has the same fields for every conference, with or without AI: `base` 10, the same `overdraft` burst on the bought part, and `level` `full` refusing new conferences with `CONFERENCE_POOL_LIMIT_REACHED`.
  - `usage_service` (`UsageServiceInfo`): `contact` (`leased`, `unreported` while reports don't get through and the last share with its burst holds, `lapsed` after 7 days without contact, `air-gapped`; may gain values), `last_contact_time` and `grace_end_time` (the 7 days without contact run from the first to the second), `share` and `share_ceiling` (this instance's share and the most it may hold with the burst), `pool_in_use` and `instances` (across the license at the last report), `pause_time` (Synauson's outage notice is up: the 7 days are paused), `refuse_time` (the service refuses the license: the 7 days run from then at the latest), `problem`, and the conference pool's `conference_share`, `conference_share_ceiling` and `conference_pool_in_use`. An instance that holds no conference share, leased or kept from its last lease, starts no conference, unless the conference pool is unlimited or the license air-gapped (and `synauson.v1.Syn` health is NOT_SERVING meanwhile). Unset in test builds with a fixed license.
  - `capabilities`: each entitlement code (`FEATURE_VAD`, `FEATURE_TURN_DETECTION`, `FEATURE_STT`, `FEATURE_TTS`), whether new work may use it (always, except while `rejected` or `disconnected` or on an expired developer license), and `included_by`: the code that grants it when the license doesn't name it itself. An entitlement includes what it depends on, transitively: `FEATURE_STT` and `FEATURE_TTS` each include turn detection, which includes VAD. `FEATURE_TTS` licenses a speaker (`DetectorConfig.tts`).
  - `models`: each model's id, `variant` (the build this machine runs: `cpu`, `int8` or `fp32`, also its directory in the store), `release` (the model's version), and state (`ready`, `downloading`, `missing`, `invalid`, `not-entitled`) with the reason. A failed download keeps `missing` or `invalid`, and its `detail` says why and when it is retried.
  - `onnx_runtime`: the ONNX Runtime library the server loaded: state (`loaded`, `unavailable`), version, file path, the release Synauson ships (`shipped_version`), and a detail when it is unavailable or another ONNX Runtime library is loaded too. Another version runs, but model speed and outputs can differ.
  - `stt` (`SttCapacityInfo`): STT's decoding pool and how many streams this machine transcribes in real time. `state` is `ready`, `loading` (calibrating and loading the workers' models in the background; an STT participant added meanwhile fails at once with `UNAVAILABLE`, `MODEL_LOADING`), `idle` (not started: no license or model yet, `detail` says which) or `failed` (the next STT participant tries again). `source` says where the numbers came from (set with `--stt-workers`, `--stt-threads` and `--max-stt-streams` is `override`): `auto` (timed on this start), `cached` (every timing read from the calibration cache in `--state-dir`) or `override`. `workers`, `threads_per_worker`, `real_time_factor` (one stream's decode time over audio time), `model_bytes` (the private memory each worker's model adds; weights shared through the model store are paid once and not counted), `shared_model_bytes` (those shared weights, so the pool's model memory is about `workers` x `model_bytes` + `shared_model_bytes`; 0 when each worker loads its own) and `limited_by` (`cpu`, `memory` or `operator`) are set once known; `streams` is the stream cap and current use. `turn_flush` says whether turns close early on forecasts, `eager` whether participants with STT may turn eager end of turn on (`--stt-eager`), and `forecast_reserve` how much decoding the cap sets aside per stream for their forecasts, at most one per pause, as a share of the stream's own (0 when both are off; absent when the operator set the capacity). Each STT participant also takes a license session. How the numbers are derived: [deployment, STT capacity](deployment.md#stt-capacity).
  - `resources` (`ResourcesInfo`): what this instance may use, detected at startup: `cpu_budget` (cores, fractional with a CPU quota), `cpu_source` (`auto` or `override`), `limited_by` (what set it: `cpu_max`, `cpuset`, `affinity`, `job_cpu_rate` (a Windows job object's CPU cap, in jsyn), `std_parallelism` or `override`), `cores` (the whole cores the model pools size by), `logical_cpus`, `physical_cores` and `performance_cpus` (where known), `cpu_model`, `cpu_flags` (the ISA extensions ONNX Runtime picks kernels by), and `memory_limit_bytes` with `memory_source`. The budget flags: [deployment](deployment.md).
  - `calibration` (`CalibrationInfo`): the calibration cache, `file` (`<state-dir>/calibration.json`, absent without a state directory) and `recalibrate` (`--recalibrate`), and the detector timings once taken: `vad` (one VAD chunk, 32 ms of audio) and `turn_detection` (one turn detection decision), each a `DetectorTiming` with the `model`, its ONNX Runtime `threads`, `run_ms` and `source` (`auto` or `cached`). How the cache is keyed: [deployment, The calibration cache](deployment.md#the-calibration-cache).
  - `tts` (`TtsCapacityInfo`): TTS's synthesis pool. `state` as for `stt` (a TTS participant added while it is `loading` fails with `MODEL_LOADING`), `workers`, `threads_per_worker`, and `streams`: the cap on utterances synthesising at once and how many are. A speaker takes a place only while it speaks, from its utterance's first chunk until the utterance is played or interrupted. How the numbers are derived: [deployment, TTS capacity](deployment.md#tts-capacity).
- Starting a conference or adding any participant while the license is `rejected` or `disconnected`, or is an expired developer license, fails with `FAILED_PRECONDITION`, reason `LICENSE_REJECTED`, `LICENSE_DISCONNECTED` or `LICENSE_EXPIRED` (metadata `license`), the message naming the state. A new AI session past the limit and its burst fails with `RESOURCE_EXHAUSTED`, `SESSION_LIMIT_REACHED`, and a new conference past the conference limit and its burst with `CONFERENCE_POOL_LIMIT_REACHED` (both with metadata `inUse`, `limit`, `ceiling`, `scope`, `license`). While this instance holds no share of a pool yet (none leased since it started, or the only share it holds was leased under the license's earlier terms), new work from that pool fails with `UNAVAILABLE`, `LICENSE_SHARE_PENDING` (metadata `pool`, `scope`, `license`): retry later or use another instance, since the pool isn't full; running sessions and conferences are never stopped, and a full conference pool never refuses a participant joining a running conference.
- An illegal license (missing `purchasedSessions`, retired limit keys such as `maxSessions`, entitlements that don't cover every feature, ...) stops the server at startup with every problem listed; the JNI adapter throws `FailedPreconditionException` with reason `ILLEGAL_LICENSE` (JNI only, like `NO_LICENSE` and `HANDLE_CLOSED`; the gRPC API never sends them). JNI throws `PermissionDeniedException` for every license refusal (`LICENSE_REJECTED`, `LICENSE_DISCONNECTED` and `LICENSE_EXPIRED`), as it did before reasons, and `FailedPreconditionException` for `MODEL_LOADING` and `LICENSE_SHARE_PENDING` (both retryable); every JNI exception message starts with the reason, which jsyn's `JSynException.reason()` returns.

## Participant lifecycle

### `AddFileParticipant`
- **Request**: `AddFileParticipantRequest { conference_id, participant_id, uri, loop_playback, detectors }`
- **Response**: `AddFileParticipantResponse { participant_id }`
- **Formats**: WAV (PCM, A-law or mu-law), Ogg Opus, Ogg Vorbis, FLAC and MP3, the royalty-free LGPL set. The server builds only the GStreamer parsers and decoders for these, whichever GStreamer it runs on, so a file in any other format (AAC or M4A, for one) is refused before anything decodes it.
- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (a URI without a scheme, a `file:` URI naming a directory, a file that can't be opened, a file in a format not listed above, its message naming what the file is), `CONFERENCE_NOT_FOUND`, `FILE_NOT_FOUND` (metadata `uri`), `PARTICIPANT_ALREADY_EXISTS` (the id is a participant, a reservation or a speaker id), `PARTICIPANT_LIMIT_REACHED` (max-participants cap), `PARTICIPANT_START_FAILED` (no audio decoded within 10 s), `LICENSE_REJECTED`, `LICENSE_DISCONNECTED`, `LICENSE_EXPIRED` (the license starts nothing new), `INTERNAL`, plus the detector errors (see [Detector configuration](#detector-configuration)).

### `AddRecordingParticipant`
- **Request**: `AddRecordingParticipantRequest { conference_id, participant_id, source_participant_id, output_path }` (`detectors`, which a recording ignored, is removed: put detectors on the source participant)
- **Response**: `AddRecordingParticipantResponse { participant_id }`
- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (an empty `output_path`, one whose directory doesn't exist, a source with no audio of its own such as another recording), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND` (the source), `PARTICIPANT_ALREADY_EXISTS`, `SIP_RESERVATION_NOT_CONNECTED` (the source), `PARTICIPANT_LIMIT_REACHED`, `LICENSE_REJECTED`, `LICENSE_DISCONNECTED`, `LICENSE_EXPIRED` (the license starts nothing new), `INTERNAL`.

### `RemoveParticipant`
- **Request**: `RemoveParticipantRequest { conference_id, participant_id }`
- **Response**: `RemoveParticipantResponse {}`
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`.

## Routing

### `MuteParticipant`
- **Request**: `MuteParticipantRequest { conference_id, participant_id, muted: bool }`
- **Response**: `MuteParticipantResponse {}`
- **Semantics**: Outgoing only: listeners stop hearing this participant, while its own detectors and speech to text still hear it. The mute belongs to the participant, not to its routes, so it holds on every route from it, including routes added later (by `SetAudioRoutes` or `AddRecordingParticipant`), until it is unmuted. Unmuting gives each route back its own `muted` from the matrix. Any kind of participant can be muted, native ones included (a recording has no audio of its own, so muting it changes nothing). A SIP reservation can be muted too and stays muted once it connects. The mute is forgotten when the participant is removed, or when a reservation is released or fails to connect, so an id used again starts unmuted. A speaker id isn't a participant: mute its routes in the matrix.
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND` (an id that isn't a participant or reservation in the conference, a speaker id included).

### `SetAudioRoutes`
- **Request**: `SetAudioRoutesRequest { conference_id, routes: [AudioRoute] }`, at most 4096 routes
- **Response**: `SetAudioRoutesResponse {}`
- **Semantics**: Replaces the whole N-to-M routing matrix (AIP-136 gives no standard verb for a replace-everything call, so the name says it): the server diffs against current state; routes in current-but-not-desired are removed, routes in desired-but-not-current are added, routes in both take the request's `muted`. An empty `routes` removes every route, and a route left out is removed: always send the whole matrix. A route carries audio only when neither its `muted` nor its source's `MuteParticipant` mute is set. Retry-safe.
- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (more than 4096 routes, a source with no audio of its own, a recording; a destination that can't receive audio, a file participant), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND` (a participant the matrix names), `SIP_RESERVATION_NOT_CONNECTED`, `INTERNAL`. Every entry is checked before anything changes, so a refused matrix leaves the routing as it was.

## File-specific

### `AddPriorityAudioFiles`
- **Request**: `AddPriorityAudioFilesRequest { conference_id, participant_id, uris: [string] }`
- **Response**: `AddPriorityAudioFilesResponse {}`
- **Semantics**: Append-to-queue. Priority files play in queue order and the participant's own audio is not heard until the queue drains. Its file keeps advancing underneath, so it does not resume where it stopped, and one that reaches its end meanwhile has ended when the queue drains (a looping file then starts over). New AddPriorityAudioFiles calls during active priority playback append to the queue. Each priority file fires `FileEvent::PlaybackStarted { uri }` and `PlaybackEnded { uri }` on the FileEvents stream. A priority file that can't be opened or decoded, or isn't in a format `AddFileParticipant` accepts, fires `FileError` and is skipped: the next one plays, or the original resumes.
- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (no URIs, more than 64, a URI as for `AddFileParticipant`), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`, `FILE_NOT_FOUND` (every URI is checked before any plays), `FILE_PARTICIPANT_REQUIRED`. Not retry-safe: a retry queues the files again.

## SIP media endpoint

### `AddSipParticipant`
- **Request**: `AddSipParticipantRequest { conference_id, participant_id, remote_ip, remote_rtp_port, codec, dtmf_payload_type, srtp?, detectors? }`
- **Response**: `AddSipParticipantResponse { participant_id, local_rtp_port }`
- **Semantics**: Adds a bidirectional RTP media participant. The caller handles all SIP signaling (INVITE/BYE) and passes pre-negotiated parameters. `remote_ip` is an IPv4 or IPv6 address, or a host name the server resolves (the name says IP for the SDP `c=` line it comes from). `local_rtp_port` is the port Synauson bound for RTP receive; the caller puts it in the SDP answer `m=` line. RTCP is on `local_rtp_port + 1`. Codecs: `"PCMU"` (PT=0, 8kHz), `"PCMA"` (PT=8, 8kHz), `"OPUS"` (PT=96, 48kHz). `dtmf_payload_type` enables RFC 4733 telephone-event RTP (typically 101) on the codec's RTP clock, as the events share the audio's SSRC and timestamps: `telephone-event/8000` with PCMU and PCMA, `telephone-event/48000` with Opus; 0 disables RFC 4733.
- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (an empty `remote_ip`, unsupported codec, port out of range), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_ALREADY_EXISTS`, `RTP_PORTS_EXHAUSTED` (metadata `portMin`, `portMax`), `PARTICIPANT_LIMIT_REACHED`, `PARTICIPANT_START_FAILED`, `LICENSE_REJECTED`, `LICENSE_DISCONNECTED`, `LICENSE_EXPIRED` (the license starts nothing new), `INTERNAL`, plus the detector errors.

### `ReserveSipParticipant`
- **Request**: `ReserveSipParticipantRequest { conference_id, participant_id, local_srtp_key?, srtp_crypto_suite }`
- **Response**: `ReserveSipParticipantResponse { participant_id, local_rtp_port, local_rtcp_port }`
- **Semantics**: First half of the two-phase add for outbound calls, where Synauson's SDP offer must carry its port before the peer's answer names its own. Allocates and binds the RTP/RTCP port pair and starts nothing; RTP the peer sends early queues on the bound socket until `ConnectSipParticipant`. `local_srtp_key` (30 bytes, `AES_CM_128_HMAC_SHA1_80`, the only suite; `srtp_crypto_suite` may be empty or that name) is the key the offer advertises. A reservation is not a participant: `GetConference` and snapshots leave it out, but it holds its id and a max-participants slot: every other add refuses the id, and counts the reservation toward the cap. `RemoveParticipant` releases it, as does `TerminateConference`.
- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (key not 30 bytes, unsupported suite), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_ALREADY_EXISTS` (id is a participant or already reserved), `RTP_PORTS_EXHAUSTED`, `PARTICIPANT_LIMIT_REACHED`.

### `ConnectSipParticipant`
- **Request**: `ConnectSipParticipantRequest { conference_id, participant_id, remote: SipRemoteMedia { remote_ip, remote_rtp_port, codec, dtmf_payload_type, remote_srtp_key? }, detectors? }`
- **Response**: `ConnectSipParticipantResponse { participant_id, local_rtp_port }`
- **Semantics**: Second half of the two-phase add: builds and starts the reserved participant on its reserved ports, from the media the peer's SDP answer negotiated. Behaves as `AddSipParticipant` from then on, sending RTP and RTCP from the reserved ports it receives on (symmetric RTP and RTCP, RFC 4961). `remote.remote_srtp_key` is required exactly when the reservation carried `local_srtp_key`. The SRTP keys are `local_*` (Synauson encrypts with them) and `remote_*` (the peer's), as the ports are; `SrtpConfig` has `local_key` and `remote_key`. Invalid arguments (including an SRTP mismatch) leave the reservation in place; any other failure releases it, and the caller must reserve again.
- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (missing `remote`, a malformed field, unsupported codec, port or DTMF payload type out of range, key not 30 bytes, SRTP on one side only), `CONFERENCE_NOT_FOUND`, `SIP_RESERVATION_NOT_FOUND`, `PARTICIPANT_ALREADY_EXISTS` (the id is a running participant; a reservation connects once), `PARTICIPANT_START_FAILED`, `INTERNAL`, plus the detector errors. It never fails on the max-participants cap: the reservation already holds its slot.

### `SendDtmf`
- **Request**: `SendDtmfRequest { conference_id, participant_id, digit, duration_ms }`
- **Response**: `SendDtmfResponse {}`
- **Semantics**: Send a DTMF digit to the remote RTP endpoint of a SIP participant. Digit must be one of `0-9`, `*`, `#`, `A`, `B`, `C`, `D`. `duration_ms` is clamped to [70, 500] per ITU-T Q.24. Uses RFC 4733 telephone-event RTP packets if `dtmf_payload_type > 0` was configured at AddSipParticipant time; otherwise uses in-band audio tones via `dtmfsrc`. Not retry-safe.
- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (invalid digit, metadata `field` `digit`), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND` (no SIP participant with that id).

### `GetSipStats`
- **Request**: `GetSipStatsRequest { conference_id, participant_id }`
- **Response**: `GetSipStatsResponse { stats: SipStats { participant_id, packets_received, packets_lost, avg_jitter_ns, active_ssrc_count } }` (`rtt_ms`, never measured, is removed, in jsyn too)
- **Semantics**: Returns current RTP receive metrics from the participant's jitter buffer (all 0 until RTP arrives).
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`.

## WebRTC media endpoint

### `AddWebRtcParticipant`
- **Request**: `AddWebRtcParticipantRequest { conference_id, participant_id, sdp_offer, detectors?, options? }`
- **Response**: `AddWebRtcParticipantResponse { participant_id, sdp_answer }`
- **Semantics**: Adds a bidirectional WebRTC participant to a conference. The browser (or any WebRTC peer) is the offerer; the gRPC caller relays the SDP offer to Synauson, gets back Synauson's SDP answer, and forwards it to the browser via `setRemoteDescription`. Codec is Opus-only (PT negotiated, typically 111): an offer without Opus audio, or whose audio section has no direction attribute, is refused, never answered without Synauson's audio. RFC 4733 telephone-event is not negotiated, so a WebRTC peer sends no DTMF. DTLS-SRTP, ICE, and RTCP are handled internally by webrtcbin. Synauson applies SSRC/MSID fixups to the answer (a webrtcbin workaround) so the browser's `MediaStreamTrack.muted` correctly transitions to false.
- **Options**: every field of `WebRtcOptions` is optional. An unset field takes the server's `--webrtc-*` default, then the built-in default:

  | Field | Built-in default | Effect |
  |---|---|---|
  | `stun_server` | `--webrtc-stun-server`, else none | `stun://host[:port]`; `""` turns STUN off. The browser form `stun:host` is rejected. Without STUN Synauson offers only its host candidates; set one when the peer reaches Synauson through NAT. |
  | `turn_servers` | none | `turn(s)://user:password@host[:port][?transport=udp\|tcp]`. Percent-encode any `: @ / ? #` in the user or password (a TURN REST name `timestamp:user` is `timestamp%3Auser`). At most 8 relays; `turn://` without a transport counts as two. |
  | `ice_transport_policy` | `ALL` | `RELAY` offers only TURN candidates, so the peer never sees Synauson's addresses, and skips STUN. Needs a TURN server. |
  | `ice_port_min`, `ice_port_max` | `--webrtc-ice-port-min/max`, else any port | Local ICE ports, 1 to 65535, set both or neither. The UDP port the call's RTP, RTCP and DTLS flow on is one of them, unless the pair ICE selects is relayed. |
  | `jitter_buffer_ms` | `--webrtc-jitter-buffer-ms` (200) | Receive jitter buffer, 0 to 2000 ms. Every mix of this participant's audio waits for it, so the others hear it late by the same amount. |
  | `opus_bitrate_bps` | 64000 | Bitrate of the Opus audio Synauson sends, 4000 to 650000 bits per second (jsyn calls it `opus_bitrate`). |
  | `opus_dtx` | true | Discontinuous transmission: packets of one or two bytes during silence. |
  | `opus_inband_fec` | false | In-band forward error correction in the audio Synauson sends. |
  | `opus_packet_loss_percentage` | 10 with FEC, else 0 | Expected loss, 0 to 100, which sizes the FEC. libopus adds no FEC at 0. |

- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (an invalid option, with metadata `field` such as `options.ice_port_min` and a BadRequest violation; an empty `sdp_offer`, or one that isn't SDP, doesn't offer exactly one media section, audio, that webrtcbin refuses or can't answer, that has no Opus audio, or whose audio section has no direction; no message or metadata contains TURN credentials or the SDP), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_ALREADY_EXISTS`, `PARTICIPANT_LIMIT_REACHED`, `LICENSE_REJECTED`, `LICENSE_DISCONNECTED`, `LICENSE_EXPIRED` (the license starts nothing new), `INTERNAL`, plus the detector errors.

### `AddWebRtcIceCandidate`
- **Request**: `AddWebRtcIceCandidateRequest { conference_id, participant_id, candidate, sdp_mline_index }`
- **Response**: `AddWebRtcIceCandidateResponse {}`
- **Semantics**: Forward a single ICE candidate from the browser to Synauson's webrtcbin. Trickle pattern; called per `icecandidate` event on the browser side. Retry-safe: libnice updates a remote candidate it already has instead of adding it twice.
- **Errors**: `INVALID_ID`, `INVALID_ARGUMENT` (empty `candidate`, negative `sdp_mline_index`), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`.

### `StreamWebRtcIceCandidates`
- **Request**: `StreamWebRtcIceCandidatesRequest { conference_id, participant_id }`
- **Response stream**: `WebRtcIceCandidate { participant_id, candidate, sdp_mline_index, end_of_candidates }`
- **Delivery**: Best-effort broadcast with replay buffer. Synauson emits each ICE candidate as webrtcbin discovers it; the gRPC caller forwards to the browser via `pc.addIceCandidate()`. Final event has `end_of_candidates = true` and empty `candidate`. Subscribers are replayed any candidates emitted before subscription, then receive new ones live. No heartbeat. Lagged subscribers get `SUBSCRIBER_LAGGED` and should subscribe again.
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND` (no WebRTC participant with that id).

### `GetWebRtcStats`
- **Request**: `GetWebRtcStatsRequest { conference_id, participant_id }`
- **Response**: `GetWebRtcStatsResponse { stats: WebRtcStats { participant_id, ice_connection_state, connection_state, packets_received, packets_lost, packets_sent, bytes_received, bytes_sent, max_jitter_ns, rtt_ms, effective_options } }`
- **Semantics**: Returns the participant's latest ICE and connection states, and the counters from webrtcbin's `get-stats`: packets and bytes received (summed over the peer's SSRCs) and sent, packets lost (the receive jitter buffer's count), the largest receive jitter, and the round-trip time once the peer's first RTCP receiver report has arrived (0 before; under 0.5 ms rounds to 0). A counter webrtcbin can't report yet is 0. The sent counters count the RTP Synauson actually sent. With nothing routed to the participant, Synauson sends Opus DTX silence on GStreamer 1.26 (Windows, the container) but no RTP at all on GStreamer 1.24 (Ubuntu 24.04's packages), so there `packets_sent` and `bytes_sent` stay 0 until a route to it carries audio. `effective_options` (`WebRtcEffectiveOptions`) reports the options the participant runs with: the ICE port range, jitter buffer and Opus fields are read from the live media elements, and the STUN, TURN (credentials redacted) and policy fields are the resolved values Synauson applied.
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`.

## Event streams (server-streaming)

Every event carries `event_time` (a Timestamp). The envelope (conference, participant, time) takes field numbers 1 to 9 and the oneof cases 10 and up. None of these streams has a heartbeat: they send nothing between events.

### `StreamFileEvents`
- **Request**: `StreamFileEventsRequest { conference_id, participant_id }` (empty `participant_id` filters to all participants in the conference)
- **Response stream**: `FileEvent` (oneof: `PlaybackStarted`, `PlaybackEnded`, `Eos`, `Error`). `Error` comes when a file can't be played: no audio could be decoded from it when it was added (the add fails too), or its decoder failed while it played.
- **Delivery**: Lossless mpsc-per-subscriber. Each event names its file participant, also with an empty filter. A slow client (>100ms per receive) is dropped without affecting other subscribers: its stream ends with `SUBSCRIBER_LAGGED`, and it should subscribe again.
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`. The stream itself closes cleanly on TerminateConference.

### `StreamVadEvents`
- **Request**: `StreamVadEventsRequest { conference_id, participant_id }`
- **Response stream**: `VadEvent` (oneof: `SpeechStart { confidence }`, `SpeechEnd { duration_ms }`). `SpeechEnd.duration_ms` is the length of the speech that ended, from its onset to where the silence began, in the audio's running time, so speech across a looping file's rewind counts whole (VAD reports the end once that silence has lasted `VadConfig.min_silence_ms`).
- **Delivery**: Best-effort broadcast (advisory events). Lagged subscribers get `SUBSCRIBER_LAGGED` (metadata `skippedEvents`) and should subscribe again.
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`, `VAD_REQUIRED` (the participant exists without `vad`).

### `StreamTurnDetectionEvents`
- **Request**: `StreamTurnDetectionEventsRequest { conference_id, participant_id }`
- **Response stream**: `TurnDetectionEvent { probability, turn_complete }`
- **Delivery**: Best-effort broadcast, as `StreamVadEvents`.
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`, `TURN_DETECTION_REQUIRED`.

### `StreamTranscriptEvents`
- **Request**: `StreamTranscriptEventsRequest { conference_id, participant_id }`
- **Response stream**: `TranscriptEvent { conference_id, participant_id, event_time, oneof event { delta: TranscriptDelta, turn: TurnTranscript } }`
- **Times** are transcription audio time: milliseconds of the participant's audio since transcription started on it, not the agent stream's conference time (the agent stream's words carry conference time; a mapping between the two can be added later without a break). Silence the transcription skipped (a gap in the audio longer than the model's left context) still counts, so times line up with the call.
- **`TranscriptDelta { text, tentative, start_ms, last_start_ms, decoded_ms, backlog_ms }`**: newly committed text, in order. Committed text is never revised, so a participant's deltas concatenate to its transcript; word-initial pieces start with a space. `tentative` is the model's current guess at what follows and replaces the previous one; it is always empty from models that don't revise (the default STT model). `start_ms` and `last_start_ms` are where the first and last piece of `text` start, `decoded_ms` how much audio is transcribed, and `backlog_ms` how much is waiting: a growing backlog means the machine can't keep up.
- **`TurnTranscript { text, start_ms, last_start_ms, turn_end_ms, probability?, complete }`**: one per turn the participant's agent stream ends (a complete turn detection decision, the end-of-turn timeout or `ForceEndTurn`; see the voice-agent stream below), sent after the deltas it covers (except forecast words; see the turn flush below). The model commits a word some time after it is spoken (for the default model, up to about 800 ms after a word that ends before a pause), so the turn is cut where the speech is, not at a time: its text is the committed text up to where VAD heard the next speech start, without splitting a word, plus a late first word of its last stretch of speech. Synauson waits up to `SttConfig.turn_drain_ms` (default 1000 ms) after the turn's end for that text to settle: when the next word arrives, or once the transcription has passed the turn's speech end by the model's commit delay. Without new speech that is about a second after the speech ended, unless the turn flush (below) closes it sooner. A turn that runs out of that time closes with what was committed (`complete` false), and its late words open the next turn; it never ends inside a word: if its last word may still continue, it waits up to two of the model's chunks more (320 ms for the default model) for it, then leaves that word, whole, to the next turn (unless it is the turn's only word). A turn's text never starts with punctuation: the model commits the punctuation ending a sentence with the next word, so turns may end without a period, and the next turn leaves it out. The deltas still carry every piece once, and the turns' texts are the deltas' text up to the last turn, in order, less the punctuation each turn's share of it starts with. `start_ms` and `last_start_ms` are the first and last piece's start (0 when `text` is empty), `turn_end_ms` where the turn ended (for a late turn, below, where the turn before it ended), `probability` turn detection's score for its last pause (unset when turn detection never decided on one, as `AgentEndOfTurn.probability`).
- **Turns closed early (the turn flush)**: off by default. When it is on and a turn ends whose text hasn't settled yet, Synauson forecasts its last words: it decodes a copy of the participant's transcription with silence after the audio so far, faster than real time, and closes the turn on what that copy commits instead of waiting for the call's own audio to get there (`--stt-turn-flush`, jsyn `sttTurnFlush`; models whose transcription state can't be copied always wait). Such a turn is `complete`, and it can arrive before the deltas of its last words, which come when the transcription commits them. Its forecast words are checked one by one against what the transcription then commits: when they match, the deltas carry them as usual and no later turn repeats them. When the participant went on speaking and the transcription commits something else in their place, the turn keeps the forecast text it was sent with (it is never resent or revised); the deltas carry what was committed, and those words open the next turn's text, so the next turn may start with a word the previous turn ended with. Only then do the turns' texts differ from the deltas'.
- **When transcription lags**: if the turn's text hasn't settled within `turn_drain_ms`, the turn is sent anyway with the text committed so far and `complete = false`. Words of that turn committed later arrive as deltas as usual and open the next turn's text; nothing is lost or repeated. If the participant says nothing more before the transcription has passed the turn's end (by the model's commit delay plus a chunk), those words don't wait for the next turn: they go out as a *late turn* of their own, a `TurnTranscript` (`complete` true) and a turn on the voice-agent stream (below). Turns are always sent in order. At the end of the participant's audio (a file's end) everything is transcribed and the remaining turns are complete, and words no turn took go out as one late turn; when the participant is removed, turns still waiting are sent at once, then any words no turn took, as a late turn or, if the participant was mid-turn, as the rest of that turn. So every committed word reaches a turn.
- **Delivery**: Best-effort broadcast, like the detector streams: subscribe before the audio you need starts. Lagged subscribers get `SUBSCRIBER_LAGGED` and should subscribe again.
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`, `STT_REQUIRED`.

### `StreamDtmfEvents`
- **Request**: `StreamDtmfEventsRequest { conference_id, participant_id }`
- **Response stream**: `DtmfEvent { participant_id, digit, in_band }` (`duration_ms`, never measured, is removed)
- **Delivery**: Best-effort broadcast. `in_band = true` for SpanDSP-detected in-band tones; `false` for RFC 4733 telephone-event packets. Lagged subscribers get `SUBSCRIBER_LAGGED` and should subscribe again.
- **Errors**: `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND` (no SIP participant with that id).

## Voice-agent event stream

One ordered stream of events per participant, for an agent that talks with it, defined in `agent.proto`. It carries speech activity, the turn lifecycle (with eager end of turn when asked for), when STT runs each turn's words, and when the participant has a speaker what it played. Clients must ignore `oneof` cases they don't know. jsyn delivers the same events and commands (`Conference.streamAgentEvents`, `forceEndTurn`, `updateTurnConfig`, `speak`, `cancelUtterance`).

### `StreamAgentEvents`
- **Request**: `StreamAgentEventsRequest { conference_id, participant_id, after_seq?, stream_id?, heartbeat_ms? }`
- **Response stream**: `AgentEvent { conference_id, participant_id, stream_id, seq, event_time, oneof event }`. The participant needs `turn_detection` in its `DetectorConfig` (and `vad`, which drives it).
- **Events**:

  | Case | Fields | When |
  |---|---|---|
  | `subscribed` | `oldest_seq`, `last_seq`, `stt`, `tts`, `voice?` | First on every subscription: the oldest event the stream still keeps (0 when none), its newest seq, whether STT runs on the participant, and whether it has a speaker, with the speaker's default voice. |
  | `heartbeat` | `conference_ms`, `stt_decoded_ms?`, `stt_backlog_ms?` | When nothing else was sent for `heartbeat_ms` (default 1000, clamped to 100 to 30000). With STT: the conference time transcribed up to, and the audio waiting. |
  | `error` | `reason`, `message`, `metadata`, `turn_id?` | A recoverable problem; the stream goes on. Reasons: `TURN_DETECTION_FAILED` (Turn detection stopped on the participant; turns end only by timeout or `ForceEndTurn` from then on), `TURN_DECISION_MISSING` (a speech end got no turn detection decision within 2 s; the timeout still ends the turn), `STT_STOPPED` (STT failed; turns end with the words they had, and later ones without words), `STT_LAGGING` (STT's backlog passed the participant's `turn_drain_ms`, at least 500 ms; metadata `backlogMs`, `thresholdMs`: turns may end incomplete, their late words opening the next turn, or a late turn of their own with no speech after them; sent again only after the backlog falls to half the threshold). |
  | `stream_ended` | `reason` (`PARTICIPANT_REMOVED`, `CONFERENCE_TERMINATED`; a server shutdown terminates conferences, so it ends streams with `CONFERENCE_TERMINATED`) | Last on the stream; the RPC then completes. Any other end can be resumed with the cursor. |
  | `speech_started` | `at_ms`, `probability` | VAD heard speech start (raw VAD: noise can start it too). |
  | `speech_stopped` | `at_ms`, `speech_ms` | VAD heard it stop; `speech_ms` is `at_ms` less the start's. |
  | `turn_started` | `turn_id`, `start_ms`, `word_backed` | A turn started. With STT on its first word (`word_backed` true); without STT on VAD's speech start. `start_ms` is VAD's speech start either way, except for a late turn (see Turns). |
  | `turn_words` | `turn_id`, `words`, `stt_backlog_ms?` | More of the open turn's words, each once it is complete; see Words below. |
  | `eager_end_of_turn` | `turn_id`, `text`, `words`, `speech_end_ms`, `probability?`, `latency` | The turn may have ended at a pause (`eager` on); see Eager end of turn below. |
  | `turn_resumed` | `turn_id`, `cause` (`SPEECH`, `WORDS`), `at_ms` | The turn's last `eager_end_of_turn` was premature; see below. |
  | `end_of_turn` | `turn_id`, `reason`, `text`, `words`, `start_ms`, `speech_end_ms`, `probability?`, `complete`, `latency` | The turn ended; see below. |
  | `turn_config_updated` | `config` | `UpdateTurnConfig` changed the turn config. |
  | `utterance_started` | `utterance_id`, `at_ms`, `time_to_first_audio_ms`, `egress_delay_ms?` | The speaker's first sample of an utterance played; see Playback below. |
  | `words_played` | `utterance_id`, `words` | More of the utterance's words fully played. |
  | `utterance_done` | `utterance_id`, `audio_ms`, `at_ms`, `underrun_ms` | The utterance played to its end. |
  | `utterance_interrupted` | `utterance_id`, `reason`, `heard_text`, `heard_text_end`, `heard_ms` | It stopped early: `CANCELLED` (`CancelUtterance`), `PREEMPTED` (a new utterance started while it was preemptible) or `STREAM_ENDED` (the participant or conference went; before `stream_ended`). |
  | `utterance_failed` | `utterance_id`, `code`, `message` | It failed: `TTS_UNAVAILABLE`, `SYNTHESIS_FAILED`, `UNSPEAKABLE_TEXT` (nothing to say, or a word too long for the model), `TTS_CAPACITY` (this machine's TTS capacity was in use when it was to start). |

  `subscribed` also carries `turn_config`, the config in effect. It doesn't carry the open turn or the utterances in flight, so a subscriber resuming without a cursor learns them from the next events; adding them to `subscribed` later is additive.

  The events that end a turn (`end_of_turn`) and an utterance (`utterance_done`, `utterance_interrupted`, `utterance_failed`) are closed sets in v1, so clients can track what is open by them; other cases may be added.
- **Turns**: turn ids rise by one from 1. Each `turn_started` is followed by exactly one `end_of_turn` for it, and no event of a turn (its start, its words, its errors) comes before the previous turn's `end_of_turn`; `speech_started` and `speech_stopped` carry no turn and go out at once. Speech after a pause stays in the open turn unless the pause's turn detection decision then says complete: the turn ends at that pause and the new speech opens the next. A turn ends for one `reason`:
  - `MODEL`: Turn detection's probability for a pause reached `end_of_turn_threshold`.
  - `TIMEOUT`: the participant stayed silent for `end_of_turn_timeout_ms` (default 5000; 0 turns it off) after a speech end, whatever turn detection said or whether it answered.
  - `MANUAL`: `ForceEndTurn`.
  - `STREAM_ENDED`: the participant or conference went with the turn open.

  A *late turn* holds words STT committed after the turn before it ended incomplete (`complete` false: STT lagged past `turn_drain_ms`) when the participant said nothing more (see When transcription lags above). It comes once STT has them, with no speech of its own: `start_ms` is its first word's start, `speech_end_ms` its last word's end, and its `reason` and `probability` are the turn before it's, whose pause ended its words too (`STREAM_ENDED` if there was no turn before it). It is `word_backed` and `complete` (unless the participant was removed before STT had them all), has no eager end or `latency.decision_ms`, and its `latency.drain_ms` runs from the turn before it's end. If speech starts before STT has them, they open that speech's turn instead.

  `speech_end_ms` is VAD's last speech end in the turn (when the turn ended, if the participant was still speaking), `probability` turn detection's for the turn's last pause when it decided. With STT, `end_of_turn` waits for the turn's transcript: `words` are its words and `text` is them joined by single spaces, which is its `TurnTranscript`'s text without the leading space; `complete` is the transcript's `complete` (false when STT ran out of drain time or stopped first; also false for a turn STT never closed). A turn STT finds no words in is not on this stream at all (its `TurnTranscript`, with empty text, still goes out). Without STT, `text` and `words` are empty and `end_of_turn` comes at once. `latency` holds durations: `since_speech_end_ms`, `decision_ms` (Turn detection's queue plus inference, `MODEL` only), `drain_ms` (waiting for STT) and `stt_backlog_ms`.
- **Words** (with STT): a `Word` is `{ text, start_ms, end_ms, confidence? }`: the word with its punctuation and no leading space (`Hello,`), the ends of the sentence before it left out at a turn's start as `TurnTranscript` does. A word goes out in a `turn_words` once it is complete (the model committed the next word, or the turn closed), so words trail speech by one word plus the model's commit delay; a turn's last words come in a `turn_words` just before its `end_of_turn`. The `turn_words` of a turn, in order, are exactly its `end_of_turn.words`: a word once sent is never taken back or moved to another turn. Word times are when the model emitted the word, not where it was spoken: they trail the audio by up to the model's commit delay (about 800 ms for the default model before a pause, less in running speech), and rise through the stream. `start_ms` is when its first piece was emitted, `end_ms` where its last piece ends. `confidence` is the lowest of the model's probabilities for the word's pieces, in [0, 1], and absent when the model gives none; read it as a relative score (a low one flags a word worth confirming), not a calibrated probability of being right.
- **Eager end of turn** (`eager` in the turn config, off by default): a pause that may end the turn gets an `eager_end_of_turn` before turn detection confirms it, so an agent can start preparing its reply. It comes at VAD's speech end when `eager_threshold` is 0 (the default), else when turn detection's probability for the pause reaches `eager_threshold` without reaching `end_of_turn_threshold` (a pause that reaches that ends the turn with no eager end first). Its `text` and `words` are what the turn's `end_of_turn` will carry if this pause ends it: with STT, Synauson forecasts the pause's last words ahead of real time, as the turn flush does, so they come before the transcription reaches them (models whose transcription can't be forecast wait for it, and gain nothing); without STT they are empty and it comes at once. Its `words` start with the turn's `turn_words` so far and may hold words not sent yet, which follow in `turn_words` as usual. `probability` is set when it came on a turn detection decision; `latency.drain_ms` is how long STT took for the text. If the pause then ends the turn, the same forecast settles the `end_of_turn`, which follows turn detection's decision at once. If turn detection ends the turn before STT has the eager end's text (the forecast decodes past the pause, so a confident decision often comes first), no `eager_end_of_turn` is sent for that pause: the `end_of_turn` comes as soon as it would have. A `turn_resumed` takes it back: `SPEECH` when the participant speaks again and the pause's decision is incomplete (Synauson waits up to 250 ms for a decision in flight; a complete one ends the turn at the pause, and the speech opens the next turn), `WORDS` when committed words differ from its text. **An `end_of_turn`'s text is the last `eager_end_of_turn`'s unless a `turn_resumed` came between them**: if it would differ, a `turn_resumed` (`WORDS`, `at_ms` the end's time) goes out first. A turn can have several eager ends, each after a `turn_resumed`. With STT, `eager` needs the instance to reserve STT decoding for its forecasts (`--stt-eager`, or the turn flush; jsyn `sttEager`): otherwise turning it on is refused (`INVALID_ARGUMENT`, `INVALID_TURN_CONFIG` from `UpdateTurnConfig`). A participant with `eager` on forecasts every turn end's last words too, at most once per pause.
- **Playback** (with a speaker): every utterance that plays any audio gets one `utterance_started`, then its `words_played`, then exactly one of `utterance_done`, `utterance_interrupted` or `utterance_failed`; none of its events follows that. Utterances play one after another in the order they were started, so the events of utterances that play never interleave; but an utterance that fails before it plays (`utterance_failed` with no `utterance_started`) is reported as soon as it fails, which can fall between an earlier utterance's events, so match events by `utterance_id`. "Played" means the audio passed the speaker's clock-synced point, the last place Synauson can still stop it, so `heard_text` is exact; the audio leaves Synauson about `egress_delay_ms` later (the mixer it plays to its participant through), plus the network and the far end's jitter buffer. A `PlayedWord` is `{ text, text_start, text_end, start_ms, end_ms }`: the word as sent with its punctuation (`Hello,`; an entity read as several words, such as `$42.50`, is one word), its range in the utterance's text (everything its `Speak`s sent, concatenated) in Unicode code points, and where it sounds in the utterance's own audio: durations from the utterance's first sample, which gaps in playback don't move. The `words_played` of an utterance, joined, are the words of its text that were heard. `heard_text` is the text up to the end of the last fully played word (`heard_text_end` its length in code points); `heard_ms` counts partly heard words too. `time_to_first_audio_ms` runs from the utterance's first `Speak`; `underrun_ms` is silence inside the utterance while synthesis fell behind.
- **The agent decides turn ends for the older streams too**: the agent stream's turn ends are what close `TurnTranscript`s, so a timeout or `ForceEndTurn` also sends one, and a turn detection decision on a turn already ended sends none. `TurnDetectionEvent.turn_complete` uses the agent's `end_of_turn_threshold`, so `UpdateTurnConfig` changes it too.

- **Conference time**: every `*_ms` time is the conference pipeline's running time in ms, one clock for all of the conference's participants (unlike `TranscriptEvent`'s audio time). `at_ms` is where the speech really started or stopped, before VAD's debounce, so it precedes the event by up to `min_speech_ms` or `min_silence_ms`. Durations (`speech_ms`, `stt_backlog_ms`) are marked as such in the proto.
- **Ordering and seq**: events reach every subscriber in one order. `seq` rises by one with each stored event, from 1; `subscribed` and `heartbeat` are not stored and repeat the last seq the subscription has (for `subscribed`, the cursor). `stream_id` names the participant's stream: a participant removed and added again under the same id gets a new `stream_id`, and seqs start again from 1.
- **Replay and resume**: the stream keeps its last 512 events. Without `after_seq` a subscription gets every kept event, then live ones. To resume after a disconnect, send the last `seq` you processed as `after_seq` with its `stream_id`: you get exactly the events after it, none twice. A cursor older than the oldest kept event fails with `OUT_OF_RANGE` (`AGENT_REPLAY_EXPIRED`); resubscribe without one. A `stream_id` that isn't the current one fails with `FAILED_PRECONDITION` (`AGENT_STREAM_MISMATCH`): the participant was added again, so start on the new stream. An `after_seq` past the newest seq (or negative) is `INVALID_ARGUMENT`.
- **Dead streams**: a client that gets nothing, not even a heartbeat, for a few `heartbeat_ms` should cancel the stream and resume with its cursor.
- **Lag**: each subscriber has its own queue of 256 events and never slows the conference. One that falls that far behind gets the events already queued, then the stream ends with `RESOURCE_EXHAUSTED` (`AGENT_SUBSCRIBER_LAGGED`, metadata `lastSeq`); resume with that seq as `after_seq` while it is still kept.
- **Errors**: `AGENT_REPLAY_EXPIRED` (`OUT_OF_RANGE`; metadata `oldestSeq`, `lastSeq`, `streamId`), `AGENT_STREAM_MISMATCH` (`FAILED_PRECONDITION`; the current `streamId`), `AGENT_SUBSCRIBER_LAGGED` (`RESOURCE_EXHAUSTED`; `lastSeq`), `TURN_DETECTION_REQUIRED`, `INVALID_ID`, `INVALID_ARGUMENT` (a cursor past the end), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`.

### `ForceEndTurn`
- **Request**: `ForceEndTurnRequest { conference_id, participant_id }`
- **Response**: `ForceEndTurnResponse { ended, turn_id? }`: whether a turn was open, and which, if it is on the stream. With STT a turn is on the stream from its first word: one ended before any has no `turn_id`, and is sent (with its `end_of_turn`) only if STT then finds words in it. Its `end_of_turn` (reason `MANUAL`) follows on the stream: at once without STT; with STT once the transcript settles, which Synauson speeds up by forecasting the turn's last words (about 100 ms on an idle machine; at most `turn_drain_ms`). If the participant is still speaking, the speech ends where the turn did and the next turn starts at once.
- **Errors**: `TURN_DETECTION_REQUIRED`, `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`. Not retry-safe: a retry may end the turn that started after the first call.

### `UpdateTurnConfig`
- **Request**: `UpdateTurnConfigRequest { conference_id, participant_id, update: TurnConfigUpdate }`. Each field set in the update replaces the current one: `end_of_turn_threshold` and `eager_threshold` in [0, 1] with `eager_threshold` at most `end_of_turn_threshold`, `end_of_turn_timeout_ms` 0 to 60000. `eager` turns eager end of turn on or off; with STT it is refused unless the instance reserves decoding for it (`--stt-eager` or `--stt-turn-flush`).
- **Response**: `UpdateTurnConfigResponse { config, seq }`: the config now in effect, and the seq of the `turn_config_updated` event that announced it. A changed timeout applies to the open turn's current pause too.
- **Errors**: `INVALID_TURN_CONFIG` (a value out of range, or eager refused; the config is unchanged), `TURN_DETECTION_REQUIRED`, `INVALID_ID`, `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`.

### `Speak`
- **Request**: `SpeakRequest { conference_id, participant_id, utterance_id, text, release, interruptible?, preemptible?, voice?, speed? }`. The participant needs `tts` in its `DetectorConfig`. A new `utterance_id` (an id as above, never reused) starts an utterance; the same id adds text to it until it ends. `text` is written text, at most 16 KiB per `Speak` and 64 KiB per utterance; the speaker normalizes it (numbers, money, dates and codes are read as a person would) and holds back what could still change, such as a number still being written. `release` is what the text ends: `NONE` or unset (more may follow), `FLUSH` (speak everything sent so far now; the utterance stays open) or `END` (the text is complete; `utterance_done` follows its playback). `interruptible` (default true), `preemptible` (default false), `voice` (one of the model's voices, `en-us-f1` to `en-us-f11` or `en-us-m1` to `en-us-m9`) and `speed` (0.25 to 4) apply from the utterance's first `Speak` only.
- **Response**: `SpeakResponse { utterance_id, created }`, as soon as the speaker has the text: it never waits for synthesis, and a `Speak` may come while earlier utterances still play (they queue). Speech starts after a short first chunk (two words), then synthesis runs ahead of playback in doubling chunks.
- **Errors**: `TTS_REQUIRED` (no speaker), `UTTERANCE_ENDED` (the utterance was ended, or finished, was interrupted or failed), `INVALID_ID`, `INVALID_SPEAK` (metadata `utteranceId`: text over its cap, `voice` or `speed` after the first `Speak`, an unknown voice, a speed out of range, more than 64 utterances queued), `INVALID_ARGUMENT` (a `release` value the server doesn't know), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`.
- **Not retry-safe**: a timed-out `Speak` may have reached the speaker, and resending it speaks the text twice. After a lost reply, cancel the utterance or carry on with the next text.

### `CancelUtterance`
- **Request**: `CancelUtteranceRequest { conference_id, participant_id, utterance_id? }`; without an id, every interruptible utterance, playing or queued.
- **Response**: `CancelUtteranceResponse { cancelled }`: each canceled utterance's `utterance_id`, `heard_text`, `heard_ms` and the `seq` of its `utterance_interrupted`, which is on the stream before the response. Empty when the utterance had already finished. The audio stops within one 20 ms buffer of the command reaching the conference, plus what the participant's mixer already holds (20 ms on SIP, 60 ms on WebRTC); the rest of the call's audio is untouched.
- **Errors**: `UNKNOWN_UTTERANCE` (an id the speaker never had), `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`, `INVALID_ID`, `TTS_REQUIRED`, `UTTERANCE_NOT_INTERRUPTIBLE` (spoken with `interruptible` false).

## Detector configuration

`DetectorConfig` is the `detectors` field on `AddFileParticipant`, `AddSipParticipant`, `ConnectSipParticipant` and `AddWebRtcParticipant`. It carries:

- `vad: VadConfig { threshold?: f32, min_silence_ms?: i32, min_speech_ms?: i32 }`: unset fields take 0.5, 300 and 100; `threshold` must be in (0, 1) and the debounces 0 to 10000 ms (others fail with `INVALID_ARGUMENT`, in jsyn too).
- `turn_detection: TurnDetectionConfig { buffered_samples: i32, confidence_threshold?: f32 }`; `confidence_threshold` is 0.5 when unset, and 0 ends the turn at every pause. `buffered_samples` is the audio (16 kHz samples) the participant must have sent before turn detection decides: 0 means the model's minimum (4000, 250 ms), smaller values are raised to it, and more than 128000 (the model's 8 s window) or below 0 is `INVALID_ARGUMENT`.
- `stt: SttConfig { turn_drain_ms?: i32 }`: streaming speech-to-text, read with `StreamTranscriptEvents`. `turn_drain_ms` (0 to 10000, default 1000) is how long a turn's transcript waits for its text to settle.
- `tts: TtsConfig { voice?, speed?, speaker_id? }`: a speaker, which says what `Speak` sends into the call. `voice` is its default voice (`en-us-f1` when unset; an unknown one fails the add with `INVALID_ARGUMENT`), `speed` its default rate (0.25 to 4, 1 when unset). The speaker plays to its own participant (SIP, WebRTC and native participants; a file participant has no output, so its speaker plays only where it is routed) and is also a routing source of its own, `speaker_id` (`<participant_id>.speaker` when unset), for `SetAudioRoutes` (to a recording, say); an id as above,; a route from it to its own participant is refused with `INVALID_ARGUMENT`. Needs `turn_detection`: its events go on the participant's agent stream. Licensed by `FEATURE_TTS`.
- `turns: TurnConfigUpdate`: the agent stream's turn config at the start, over the defaults (`end_of_turn_threshold` from `turn_detection.confidence_threshold`, timeout 5000 ms, eager off with `eager_threshold` 0); same fields and ranges as `UpdateTurnConfig`, and `eager` with `stt` refused the same way (`INVALID_ARGUMENT`). Its `end_of_turn_threshold` replaces `confidence_threshold`. Needs `turn_detection`.

Each may be omitted; all may be configured for the same participant. They form a chain, VAD <- turn detection <- STT (and turn detection <- TTS), and each needs the one below it on the same participant: Turn detection decides only when VAD reports a speech end, and turn detection's turn ends close each STT `TurnTranscript`. A participant missing one fails with `INVALID_ARGUMENT` naming both fields, e.g. `turn_detection needs vad on the same participant: set vad in its detector config`; Synauson never adds one for you. (Before this check, turn detection without `vad` was accepted and never ran.)

Licensing follows the same chain: an entitlement includes everything below it, so `FEATURE_TURN_DETECTION` also runs VAD, and `FEATURE_STT` runs turn detection and VAD as well. A participant with any detectors takes one concurrent AI session from the license's session pool, whatever it runs (see [Licensing](#licensing)); every license grants every detector, so the license decides only how many. STT also counts against this machine's STT capacity (`GetCapabilities.stt`). TTS counts against `GetCapabilities.tts` only while it speaks. TTS's engine loads in the background as STT's does, and a `tts` participant added before `GetCapabilities.tts.state` is `ready` fails with `UNAVAILABLE`, `MODEL_LOADING`. STT's decoding pool loads in the background, at startup when the license includes STT and its model is in the store (else once the model downloads, or when an STT participant is first asked for); until `GetCapabilities.stt.state` is `ready`, adding a participant with `stt` fails with `MODEL_LOADING`. A model still downloading fails the same way. Adds never wait for it.

Adding a participant with detectors can fail with:

- `INVALID_ARGUMENT`: a detector without the one it needs (`turn_detection` without `vad`, `stt` or `tts` without `turn_detection`), an unknown `tts.voice` or `tts.speed` out of range, a VAD value out of range, `turn_drain_ms` above 10000 or negative, `turns` without `turn_detection`; `INVALID_TURN_CONFIG` for `turns` out of range or eager refused; `INVALID_ID` for a bad `tts.speaker_id`.
- `LICENSE_REJECTED`, `LICENSE_DISCONNECTED`, `LICENSE_EXPIRED` (`FAILED_PRECONDITION`): the license was rejected, no usage report has reached usage.synauson.com for 7 days (`disconnected`), or a developer license expired. `FEATURE_NOT_LICENSED` (`PERMISSION_DENIED`) is the same refusal caught later, by a model that the license, turned rejected, disconnected or expired meanwhile, no longer entitles (metadata `model`).
- `MODEL_LOADING` (`UNAVAILABLE`): a model is downloading, or the STT or TTS pool is loading; retry shortly. Licensed models download in the background at startup, so this is common right after a start.
- `MODEL_UNAVAILABLE`, `ONNX_RUNTIME_UNAVAILABLE` (`FAILED_PRECONDITION`): a model is missing, fails verification, failed to download or load, the operator turned TTS off (`--max-tts-streams 0`), or ONNX Runtime is not available.
- `SESSION_LIMIT_REACHED`, `STT_CAPACITY_REACHED` (`RESOURCE_EXHAUSTED`): the license's concurrent AI sessions (beyond its burst) are in use (a participant with any detector takes one), or this machine's STT capacity is in use (metadata `inUse`, `limit`).
- `LICENSE_SHARE_PENDING` (`UNAVAILABLE`): this instance holds no share of the license's session pool yet (a participant with detectors takes a session); retry later (metadata `pool`, `scope`, `license`).

`GetCapabilities` shows which capabilities are entitled and through what, the session and conference pools' use against their limits, and each model's state.

## Admin service

`synauson.v1.SynAdmin` (`admin.proto`) holds the operator RPCs, apart from the calls agents make, so operators can keep them from agents later. Every instance serves it on the same address and behind the same auth as `Syn`.

### `ShutdownServer`
- **Request**: `ShutdownServerRequest { grace_period_seconds: i32 }`
- **Response**: `ShutdownServerResponse {}`
- Terminates every conference, waiting at most `grace_period_seconds` for them, then stops the server. The RPC returns immediately; the drain runs in the background. Health turns NOT_SERVING at once and new conferences fail with `SERVER_SHUTTING_DOWN`. Retry-safe.
- SIGTERM and SIGINT (Ctrl-C or Ctrl-Break on Windows) do the same with a 5 s grace for the conferences, so recordings in progress are finished files; health turns NOT_SERVING and new conferences are refused first.

### `GetResourceSnapshot`
- **Request**: `GetResourceSnapshotRequest {}`
- **Response**: `GetResourceSnapshotResponse { snapshot: ResourceSnapshot }` containing `capture_time`, process memory (absent off Linux), the server's thread pools (`worker_threads`, `blocking_threads`), cgroup memory (`version` a `CgroupVersion`; the limit absent when none is set, both fields absent with `NONE`), and per-conference info (at most the `--max-conferences` cap when one is set).

## Status codes and reasons

Every reason, with its code and metadata, is in `errors.proto`'s `ErrorReason`; this table is the overview.

| Code | Reasons |
|---|---|
| `INVALID_ARGUMENT` | `INVALID_ARGUMENT` (a bad field; metadata `field` and a BadRequest violation when one field is named), `INVALID_ID`, `INVALID_TURN_CONFIG`, `INVALID_SPEAK` |
| `NOT_FOUND` | `CONFERENCE_NOT_FOUND`, `PARTICIPANT_NOT_FOUND`, `SIP_RESERVATION_NOT_FOUND`, `FILE_NOT_FOUND`, `UNKNOWN_UTTERANCE` |
| `ALREADY_EXISTS` | `CONFERENCE_ALREADY_EXISTS`, `PARTICIPANT_ALREADY_EXISTS` |
| `RESOURCE_EXHAUSTED` | `CONFERENCE_LIMIT_REACHED`, `CONFERENCE_POOL_LIMIT_REACHED`, `PARTICIPANT_LIMIT_REACHED`, `RTP_PORTS_EXHAUSTED`, `SESSION_LIMIT_REACHED`, `STT_CAPACITY_REACHED`, `SUBSCRIBER_LAGGED`, `AGENT_SUBSCRIBER_LAGGED` |
| `FAILED_PRECONDITION` | `LICENSE_REJECTED`, `LICENSE_DISCONNECTED`, `LICENSE_EXPIRED`, `MODEL_UNAVAILABLE`, `ONNX_RUNTIME_UNAVAILABLE`, `VAD_REQUIRED`, `TURN_DETECTION_REQUIRED`, `STT_REQUIRED`, `TTS_REQUIRED`, `FILE_PARTICIPANT_REQUIRED`, `SIP_RESERVATION_NOT_CONNECTED`, `PARTICIPANT_START_FAILED`, `AGENT_STREAM_MISMATCH`, `UTTERANCE_ENDED`, `UTTERANCE_NOT_INTERRUPTIBLE` |

| `UNAVAILABLE` | `MODEL_LOADING`, `SERVER_SHUTTING_DOWN`, `LICENSE_SHARE_PENDING` |
| `UNAUTHENTICATED` | `INVALID_TOKEN` |
